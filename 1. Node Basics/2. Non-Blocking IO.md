# Non-Blocking I/O in Node.js

## What is Non-Blocking I/O?

One of the main reasons Node.js is fast and scalable is its **non-blocking I/O model**.

**I/O (Input/Output)** refers to operations such as:

* Reading files
* Writing files
* Database queries
* Network requests
* API calls

In a traditional **blocking** model, the program must wait for an operation to finish before moving to the next line of code.

In Node.js, most I/O operations are **non-blocking**, meaning the program can continue doing other work while waiting for the operation to complete.

---

## Blocking vs Non-Blocking

### Blocking (Synchronous)

Imagine ordering food at a restaurant and standing at the counter until your meal is ready.

You cannot do anything else until the food arrives.

```js
const user = getUserSync(1);
console.log(user);
```

Execution flow:

```text
Get user
↓
Wait until finished
↓
Print user
↓
Continue program
```

The program is paused until `getUserSync()` returns a result.

---

### Non-Blocking (Asynchronous)

Now imagine ordering food and receiving a buzzer.

While your food is being prepared, you can sit down, talk with friends, or do other things.

When the food is ready, the buzzer notifies you.

```js
getUserAsync(1, (user) => {
  console.log(user);
});
```

Execution flow:

```text
Start getting user
↓
Continue running other code
↓
User data becomes available
↓
Callback executes
```

The program does not stop while waiting.

---

## How Node.js Achieves Non-Blocking I/O

### 1. Event Loop

The **event loop** is the heart of Node.js.

It constantly checks for completed tasks and executes their callbacks.

```text
Start Program
      ↓
  Event Loop
      ↓
Waiting for Events
      ↓
Event Completed?
      ↓
Execute Callback
```

When a file read, database query, or network request finishes, the event loop runs the corresponding callback function.

---

### 2. Callbacks

A callback is simply a function passed into another function to be executed later.

Example:

```js
function greet(name, callback) {
  console.log(`Hello ${name}`);
  callback();
}

greet("John", () => {
  console.log("Callback executed");
});
```

Output:

```text
Hello John
Callback executed
```

Node.js uses callbacks extensively to handle asynchronous operations.

---

### 3. Non-Blocking APIs

Node.js provides asynchronous APIs for many common tasks.

For example, reading a file:

```js
const fs = require("fs");

fs.readFile("data.txt", "utf8", (err, data) => {
  if (err) {
    console.error(err);
    return;
  }

  console.log(data);
});

console.log("Reading file...");
```

Possible output:

```text
Reading file...
File contents here...
```

Notice that `"Reading file..."` prints immediately because Node.js does not wait for the file to finish loading.

---

### 4. Single-Threaded Architecture

Node.js runs JavaScript on a **single main thread**.

Instead of creating a new thread for every request, Node.js:

1. Starts an I/O operation.
2. Hands it off to the operating system.
3. Continues executing other code.
4. Executes a callback when the operation finishes.

```text
Request A ──┐
Request B ──┼──► Event Loop
Request C ──┘
                 ↓
          Callback Queue
                 ↓
           Execute Results
```

This allows Node.js to handle thousands of simultaneous connections with relatively low resource usage.

## Understanding the Examples

### Blocking Example

```js
const getUserSync = (userId) => {
  const users = {
    1: { name: "John", age: 35 },
    2: { name: "Jane", age: 28 }
  };

  return users[userId];
};

const user = getUserSync(1);
console.log(user);
```

What happens?

1. `getUserSync()` runs.
2. The result is returned immediately.
3. `console.log()` executes.
4. Only then does the program continue.

Output:

```text
{ name: 'John', age: 35 }
```

---

### Non-Blocking Example

```js
const getUserAsync = (userId, callback) => {
  const users = {
    1: { name: "John", age: 35 },
    2: { name: "Jane", age: 28 }
  };

  setTimeout(() => {
    callback(users[userId]);
  }, 1000);
};

getUserAsync(1, (user) => {
  console.log(user);
});

console.log("Doing other work...");
```

Output:

```text
Doing other work...
{ name: 'John', age: 35 }
```

What happens?

1. `getUserAsync()` starts.
2. `setTimeout()` schedules work for later.
3. Node.js continues executing code.
4. `"Doing other work..."` prints immediately.
5. After 1 second, the callback runs.
6. User data is printed.

The program remains responsive instead of waiting.

---

## Key Takeaways

* **I/O** includes file operations, database queries, API requests, and network communication.
* **Blocking I/O** pauses the program until an operation finishes.
* **Non-blocking I/O** allows the program to continue running while waiting for results.
* Node.js achieves this using:

  * The **Event Loop**
  * **Callbacks**
  * **Asynchronous APIs**
  * A **single-threaded architecture**
* This design makes Node.js highly efficient for servers and applications that handle many simultaneous connections.

### One-Sentence Summary

Node.js uses a non-blocking, event-driven architecture that allows it to perform I/O operations asynchronously, enabling it to handle many concurrent tasks efficiently without pausing the main program.
