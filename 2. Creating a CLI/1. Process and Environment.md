### Summary + Explanation: Node.js Process & Environment

In Node.js, the **runtime gives you access to information about how your program is running** through a special global object called `process`.

This object helps you:

* Read command-line arguments
* Access environment variables
* Control or stop the program

---

## 1. Process Object

The `process` object represents the currently running Node.js application.

### Common properties/methods:

* `process.argv` → command-line arguments
* `process.pid` → process ID
* `process.env` → environment variables
* `process.exit()` → stop the program

---

### Example: Command-line arguments

```javascript
// script.js
console.log(process.argv);
```

If you run:

```bash
node script.js arg1 arg2
```

Output:

```javascript
[
  'node',
  '/path/to/script.js',
  'arg1',
  'arg2'
]
```

### What this means:

Node automatically includes:

* The Node executable path
* The script path
* Any extra arguments you passed

---

## 2. Environment Variables

Environment variables are **external settings your app can read at runtime** (like mode, API keys, configs).

They are stored in:

```javascript
process.env
```

---

### Example: Reading an environment variable

```javascript
// script.js
console.log(process.env.NODE_ENV);
```

Run it like this:

```bash
NODE_ENV=production node script.js
```

Output:

```javascript
production
```

### What this means:

* `NODE_ENV` is set outside your code
* Node reads it through `process.env`
* Useful for switching between development and production settings

---

## Key Idea (Simple)

* `process.argv` → gives input from the command line
* `process.env` → gives configuration from the environment
* Together, they let your app behave differently without changing code

---

## Conclusion

The `process` object is how Node.js connects your program to the outside world (terminal + system environment). It’s essential for building flexible and production-ready applications.
