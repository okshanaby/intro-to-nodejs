# Async in Node.js — Simple Summary

**Asynchronous programming** allows Node.js to run tasks without blocking the rest of the program. This means Node.js can continue working while waiting for slow operations like reading files, API calls, or database queries.

---

## Key Points

* Node.js uses **non-blocking I/O**
* Async code keeps applications fast and responsive
* There are three main ways to handle async code:

  * Callbacks
  * Promises
  * Async/Await
* Error handling is done separately and is very important

---

## Why Async Matters

Node.js does not wait for slow tasks to finish before moving on.

### Synchronous (Blocking)

```js
const data = fs.readFileSync('file.txt')
console.log(data)

console.log('Done')
```

The program stops until the file is fully read.

---

### Asynchronous (Non-Blocking)

```js
fs.readFile('file.txt', (err, data) => {
  console.log(data)
})

console.log('Done')
```

Node.js continues running while the file is being read.

---

# 1. Callbacks

Callbacks are functions passed into another function and executed after the async task completes.

## Example

```js
fs.readFile('file.txt', (data) => {
  console.log(data)
})
```

### How It Works

1. File reading starts
2. Node.js continues executing other code
3. When file is ready, callback runs with the result

---

## Callback Structure

```js
function (result) {
  // runs after async task completes
}
```

---

## Key Idea

Callbacks let you handle results **after completion**, but they can become hard to manage when nested deeply.

---

# 2. Promises

Promises represent a value that will be available in the future.

## Example

```js
const fs = require('fs/promises')

fs.readFile('file.txt')
  .then(data => {
    console.log(data)
  })
```

---

## How It Works

1. Function returns a Promise
2. When complete, `.then()` runs
3. Result is passed into `.then()`

---

## Key Idea

Promises allow chaining async operations in a cleaner way than callbacks.

---

# 3. Async/Await

Async/Await is built on Promises and makes async code look synchronous.

## Example

```js
const fs = require('fs/promises')

async function readFile() {
  const data = await fs.readFile('file.txt')
  console.log(data)
}

readFile()
```

---

## How It Works

1. Function marked with `async`
2. `await` pauses execution until Promise resolves
3. Code continues after result is ready

---

## Key Idea

Async/Await makes asynchronous code easier to read and write.

---

# Error Handling

Error handling is essential for all asynchronous operations.

Without proper handling, your application may crash or behave unexpectedly.

---

## Callback Error Handling

```js
fs.readFile('file.txt', (err, data) => {
  if (err) {
    console.error(err)
    return
  }

  console.log(data)
})
```

---

## Promise Error Handling

```js
fs.readFile('file.txt')
  .then(data => {
    console.log(data)
  })
  .catch(err => {
    console.error(err)
  })
```

---

## Async/Await Error Handling

```js
async function readFile() {
  try {
    const data = await fs.readFile('file.txt')
    console.log(data)
  } catch (err) {
    console.error(err)
  }
}
```

---

## Why Error Handling Matters

* Prevents application crashes
* Helps identify issues quickly
* Improves reliability of your app
* Ensures graceful failure instead of breaking everything

---

# Comparison

| Method      | Style       | Readability       |
| ----------- | ----------- | ----------------- |
| Callbacks   | Old style   | Hard with nesting |
| Promises    | Chain-based | Better            |
| Async/Await | Modern      | Best              |

---

# One-Sentence Summary

**Async programming in Node.js lets the system handle multiple tasks without blocking, and it can be done using Callbacks, Promises, or Async/Await, while error handling is managed separately to ensure reliability.**
