# Using a File as a Database — Simple Summary

Instead of using a real database, we can store data in a **JSON file** and use Node.js `fs` module to read and write it. This is a simple way to simulate a database for small projects like a notes CLI app.

---

## 📁 Database File (`db.json`)

We start by creating a file that will act as our database:

```json
{
  "notes": []
}
```

### What this means:

* The file contains an object
* It has one key: `notes`
* `notes` is an array where all notes will be stored

---

## 🧠 DB Helper Module (`db.js`)

We create a helper file to manage reading and writing to the JSON file.

```js
import fs from 'node:fs/promises'

const DB_PATH = new URL('../db.json', import.meta.url).pathname

export const getDB = async () => {
  const db = await fs.readFile(DB_PATH, 'utf-8')
  return JSON.parse(db)
}

export const saveDB = async (db) => {
  await fs.writeFile(DB_PATH, JSON.stringify(db, null, 2))
  return db
}

export const insert = async (data) => {
  const db = await getDB()
  db.notes.push(data)
  await saveDB(db)
  return data 
}
```

---

## 🔍 Explanation of the Code

### 1. Importing `fs/promises`

We use:

```js
import fs from 'node:fs/promises'
```

### Why?

* This is the **Promise-based version** of the file system module
* It allows us to use `async/await`
* Makes code cleaner than callbacks

---

### 2. Defining the DB file path

```js
const DB_PATH = new URL('../db.json', import.meta.url).pathname
```

### What this does:

* Creates a **correct absolute path** to `db.json`
* `import.meta.url` = current file location
* `new URL(...).pathname` converts it into a usable file path

---

## 🧰 The Three Main Functions

---

### 📥 `getDB()`

```js
export const getDB = async () => {
  const db = await fs.readFile(DB_PATH, 'utf-8')
  return JSON.parse(db)
}
```

### What it does:

* Reads the `db.json` file
* Converts it from text → JavaScript object
* Returns the database object

### In simple terms:

👉 “Load the database into memory”

---

### 💾 `saveDB(db)`

```js
export const saveDB = async (db) => {
  await fs.writeFile(DB_PATH, JSON.stringify(db, null, 2))
  return db
}
```

### What it does:

* Takes a JavaScript object (`db`)
* Converts it into JSON string
* Writes it back to `db.json`

### Key part:

```js
JSON.stringify(db, null, 2)
```

* Converts object → JSON
* `null` = no filtering
* `2` = pretty formatting (readable spacing)

### In simple terms:

👉 “Save updated data back to the file”

---

### ➕ `insert(data)`

```js
export const insert = async (data) => {
  const db = await getDB()
  db.notes.push(data)
  await saveDB(db)
  return data 
}
```

### What it does step by step:

1. Loads the database (`getDB`)
2. Adds new note into `notes` array
3. Saves updated database (`saveDB`)
4. Returns the new note

### In simple terms:

👉 “Add a new note into the database”

---

## ⚙️ Flow of How It Works

When you insert a note:

```
insert(data)
   ↓
getDB() → read db.json
   ↓
add note to array
   ↓
saveDB() → write back to db.json
   ↓
return new note
```

---

## 📌 Key Idea

This approach treats a simple JSON file as a **mini database**.

It is:

* Simple
* Good for learning
* Useful for small CLI apps

But:

* Not efficient for large apps
* Not safe for concurrent writes
* Not scalable like real databases

---

## 🧾 One-Sentence Summary

Using a file as a database means reading a JSON file into memory, modifying its data in JavaScript, and writing it back to disk using Node.js `fs/promises`.
