## 📁 File Paths in Node.js (3 Common Methods)

When working with `fs`, you often need to tell Node **where a file is located**. There are 3 common ways to handle file paths.

---

## 1. Relative Path (Simple Way)

```js
import fs from 'fs'

fs.readFile('../testingFolder/new-demo.js', 'utf8', (err, data) => {
  if (err) {
    console.error(err)
    return
  }

  console.log(data)
})
```

### How it works

* Path is based on **where you run the command in terminal**
* Uses `process.cwd()`

### Pros

* Very simple
* Quick for small scripts

### Cons

* Can break depending on where you run the file

---

## 2. ES Module Safe Path (URL method)

```js
import fs from 'fs'

const DB_PATH = new URL('../db.json', import.meta.url).pathname

fs.readFile(DB_PATH, 'utf8', (err, data) => {
  if (err) {
    console.error(err)
    return
  }

  console.log(data)
})
```

### How it works

* Uses `import.meta.url` (current file location)
* Builds a reliable path relative to the file itself

### Pros

* ES module native
* No need for `__dirname`

### ⚠ Note

* Can behave differently on Windows (path formatting)

---

## 3. Recommended Safe Method (path + fileURLToPath)

```js
import fs from 'fs'
import path from 'path'
import { fileURLToPath } from 'url'

const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)

const filePath = path.join(__dirname, '../testingFolder/new-demo.js')

fs.readFile(filePath, 'utf8', (err, data) => {
  if (err) {
    console.error(err)
    return
  }

  console.log(data)
})
```

### How it works

* Converts ES module file URL into a real path
* Builds safe cross-platform file paths

### Pros

* Most reliable
* Works on Windows, Mac, Linux
* Used in real production apps

---

## 🧠 Simple Rule

* Small scripts → relative paths are fine
* ES module style → `new URL()` works
* Real projects → use `path.join + fileURLToPath`

---

## One-Sentence Summary

**Node.js supports three path methods—relative paths, ES module URL paths, and path module-based absolute paths—with the last being the most reliable for real-world applications.**
