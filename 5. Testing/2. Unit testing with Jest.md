# Unit Testing with Jest — Simple Summary

**Jest** is a popular JavaScript testing framework used to write and run tests for Node.js applications.

It helps you verify that your functions work correctly by comparing actual results with expected results.

---

## Key Points

* Jest is a testing framework for JavaScript and Node.js.
* Test files usually use the `.test.js` extension.
* Tests are commonly stored inside a `tests` folder.
* The `test()` function defines a test case.
* The `expect()` function checks whether the result matches the expected value.
* Jest can **mock** functions, allowing you to test code without using a real database or external service.
* Tests can be run using the `npm test` command.

---

# Basic Test Structure

A Jest test usually follows this pattern:

```js
test('description of test', () => {
  // Arrange (prepare data)

  // Act (run function)

  // Assert (check result)
});
```

### Example

```js
test('adds two numbers', () => {
  expect(2 + 3).toBe(5);
});
```

### Explanation

* `test()` creates a test case.
* The first argument is a description.
* `expect()` checks the result.
* `toBe()` compares primitive values such as numbers and strings.

# Example Test from the Notes

```js
test('newNote inserts data and returns it', async () => {
  const note = 'Test note';
  const tags = ['tag1', 'tag2'];

  const data = {
    tags,
    content: note,
    id: Date.now(),
  };

  insert.mockResolvedValue(data);

  const result = await newNote(note, tags);

  expect(result).toEqual(data);
});
```

### What Happens Here?

1. Create test data.
2. Mock the database `insert()` function.
3. Make the mock return predefined data.
4. Call `newNote()`.
5. Verify the returned result matches the expected data.

# Mocking in Jest

Mocking means replacing real functions with fake versions during testing.

This is useful because:

* No real database is needed.
* Tests run faster.
* Tests become predictable.
* External dependencies do not affect results.

### Mock Setup

```js
import { jest } from '@jest/globals';

jest.unstable_mockModule('../src/db.js', () => ({
  insert: jest.fn(),
  getDB: jest.fn(),
  saveDB: jest.fn(),
}));
```

### What This Does

Creates fake versions of:

```js
insert()
getDB()
saveDB()
```

instead of using the real database functions.

# Complete Test File

```js
import { jest } from '@jest/globals';

jest.unstable_mockModule('../src/db.js', () => ({
  insert: jest.fn(),
  getDB: jest.fn(),
  saveDB: jest.fn(),
}));

const { insert, getDB, saveDB } = await import('../src/db.js');
const { newNote, getAllNotes, removeNote } = await import('../src/notes.js');

beforeEach(() => {
  insert.mockClear();
  getDB.mockClear();
  saveDB.mockClear();
});

test('newNote inserts data and returns it', async () => {
  const note = 'Test note';
  const tags = ['tag1', 'tag2'];

  const data = {
    tags,
    content: note,
    id: Date.now(),
  };

  insert.mockResolvedValue(data);

  const result = await newNote(note, tags);

  expect(result).toEqual(data);
});

test('getAllNotes returns all notes', async () => {
  const db = {
    notes: ['note1', 'note2', 'note3'],
  };

  getDB.mockResolvedValue(db);

  const result = await getAllNotes();

  expect(result).toEqual(db.notes);
});

test('removeNote does nothing if id is not found', async () => {
  const notes = [
    { id: 1, content: 'note 1' },
    { id: 2, content: 'note 2' },
    { id: 3, content: 'note 3' },
  ];

  saveDB.mockResolvedValue(notes);

  const idToRemove = 4;

  const result = await removeNote(idToRemove);

  expect(result).toBeUndefined();
});
```

---

# Understanding `beforeEach()`

```js
beforeEach(() => {
  insert.mockClear();
  getDB.mockClear();
  saveDB.mockClear();
});
```

### Purpose

Runs before every test.

### Why?

Without clearing mocks:

```text
Test 1 → insert called 1 time
Test 2 → insert called 1 time

Total = 2 calls
```

This can cause incorrect test results.

`mockClear()` resets mock history before each test.

# Common Jest Matchers

### `toBe()`

Checks primitive values.

```js
expect(5).toBe(5);
```

---

### `toEqual()`

Checks objects and arrays.

```js
expect([1, 2, 3]).toEqual([1, 2, 3]);
```

```js
expect({
  name: 'John'
}).toEqual({
  name: 'John'
});
```

---

### `toBeUndefined()`

Checks if a value is `undefined`.

```js
expect(result).toBeUndefined();
```

# Running Tests

## Run All Tests

```bash
npm test
```

### What It Does

* Starts Jest.
* Finds `.test.js` files.
* Runs all tests.
* Shows passed and failed tests.

---

## Run a Specific Test File

```bash
npm test path/to/test/file
```

### Example

```bash
npm test tests/notes.test.js
```

### What It Does

Runs only the specified test file.

# Why Use Jest?

Jest helps you:

* Catch bugs early
* Test code automatically
* Avoid breaking existing features
* Test without a real database
* Improve confidence when changing code

---

# Common Rule

**A unit test should test one piece of functionality in isolation.**

Use mocks whenever possible to avoid relying on databases, APIs, or external services.
