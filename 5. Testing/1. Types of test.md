# Types of Testing — Simple Summary

**Testing** is the process of checking whether your Node.js application works correctly. Different types of tests focus on different parts of the application, from small functions to the entire system.

Using multiple types of tests helps catch bugs early and makes your application more reliable.

---

## Key Points

* Different tests serve different purposes.
* Unit tests check small pieces of code.
* Integration tests check how parts work together.
* E2E tests check the entire application from a user's perspective.
* API tests verify that endpoints and APIs behave correctly.
* A good testing strategy often uses multiple types of tests.

---

# 1. Unit Testing

**Unit testing** focuses on testing a single piece of code in isolation, usually a function, method, or module.

The goal is to make sure that each small part of your application works correctly by itself.

### Example

```js
// math.js

export function add(a, b) {
  return a + b;
}
```

```js
// math.test.js

import { add } from './math.js';

console.log(add(2, 3) === 5); // true
```

### Benefits

* Finds bugs early
* Easy to write and run
* Makes code easier to maintain
* Tests individual functionality without outside dependencies

### Focus

**"Does this single function work correctly?"**

---

# 2. Integration Testing

**Integration testing** checks whether multiple parts of the application work correctly together.

Instead of testing one function, it tests the interaction between modules, databases, APIs, or services.

### Example

```js
// userService.js

import { getUserFromDB } from './database.js';

export function getUser(id) {
  return getUserFromDB(id);
}
```

Integration testing would verify that:

```text
userService.js
        ↓
database.js
        ↓
Database
```

all work together correctly.

### Benefits

* Detects communication problems between components
* Ensures modules integrate properly
* Finds issues unit tests may miss

### Focus

**"Do these different parts work together correctly?"**

---

# 3. End-to-End (E2E) Testing

**End-to-End (E2E) testing** checks the entire application from the user's perspective.

It simulates real user actions and verifies that the complete system works correctly.

### Example Scenario

```text
User opens website
       ↓
User logs in
       ↓
Application validates credentials
       ↓
Database returns user data
       ↓
Dashboard appears
```

An E2E test verifies that the entire flow works successfully.

### Benefits

* Tests the complete application
* Mimics real-world usage
* Helps find issues that only appear in production-like environments

### Focus

**"Can a real user successfully use the application?"**

---

# 4. API Testing

**API testing** focuses on testing the application's API endpoints.

It checks whether the API:

* Accepts requests correctly
* Returns the expected responses
* Handles invalid inputs properly
* Communicates with other services correctly

### Example API Endpoint

```js
app.get('/users/:id', (req, res) => {
  res.json({
    id: req.params.id,
    name: 'John'
  });
});
```

Example request:

```http
GET /users/1
```

Example response:

```json
{
  "id": "1",
  "name": "John"
}
```

API testing verifies that the endpoint behaves as expected.

### Benefits

* Ensures APIs work correctly
* Validates request and response handling
* Detects backend issues early
* Important for applications exposing REST or GraphQL APIs

### Focus

**"Does this API endpoint return the correct result?"**

---

# Comparison of Testing Types

| Test Type           | What It Tests                        | Example                               |
| ------------------- | ------------------------------------ | ------------------------------------- |
| Unit Testing        | Individual functions or modules      | Testing an `add()` function           |
| Integration Testing | Multiple components working together | Service communicating with a database |
| E2E Testing         | Entire application workflow          | User login process                    |
| API Testing         | API endpoints and responses          | `GET /users/1`                        |

---

# Recommended Testing Pyramid

A common strategy is:

```text
       E2E Tests
           ▲
     Integration Tests
           ▲
       Unit Tests
```

### Why?

* Write many **Unit Tests** because they are fast.
* Write fewer **Integration Tests** because they take more setup.
* Write the fewest **E2E Tests** because they are slower and more complex.

---

# Why Testing Matters

Testing helps you:

* Catch bugs before users find them
* Refactor code safely
* Improve application reliability
* Reduce production issues
* Build confidence when making changes

---

# Common Rule

**The larger the scope of the test, the more parts of the application it verifies.**

* Unit Test → One component
* Integration Test → Multiple components
* E2E Test → Entire application
* API Test → Application endpoints

---

# One-Sentence Summary

**Unit tests verify individual pieces of code, integration tests verify how components work together, E2E tests verify the complete user experience, and API tests verify that application endpoints behave correctly and return the expected results.**
